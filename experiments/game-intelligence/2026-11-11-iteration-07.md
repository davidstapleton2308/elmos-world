## Hypothesis
SQLite processing leases plus idempotent classification results permit eventual recovery from a process crash without duplicate **classification records**. This does not establish exactly-once filesystem moves. A separate durable move intent and recovery protocol are required.

## Disposable executable experiment
Used Python `sqlite3` with a temporary on-disk database; three synthetic job IDs, `pending/leased/done` states, lease expiration, attempts, and an `outcomes` table keyed by job ID. All database writes were transactional. Claim at t=100, simulated crash without completion, another worker claimed a different job at t=105, first job was reclaimed after expiry at t=111, repeated completion was delivered twice, and remaining jobs were completed after expiry at t=116.

Observed final rows: `job0 done attempts=2`, `job1 done attempts=2`, `job2 done attempts=1`; **3 unique outcome records**, no duplicate outcome for job0. This is a controlled state-machine test, not a Windows crash or application integration test. A first harness mistakenly stopped at t=112 and showed only 2/3 done because job1 was still leased; the corrected harness waited past its expiry, establishing why tests must model lease time explicitly.

## Critical new failure mode
A classifier can commit its `done` result while the game folder is still being modified, and an expired worker may later write stale results. Add a monotonically increasing `lease_generation` fencing token; completion requires matching the currently owned generation and current file fingerprint. A SQLite `INSERT OR IGNORE` protects a row from duplicates, **not** against stale or incorrect results.

`os.rename` and a SQLite commit cannot be made one atomic transaction. Crash between them can leave the folder moved but no recorded move. Before any move, persist a `planned` operation with source/destination and identity; use `planned -> moving -> verified` with restart reconciliation of both paths and no blind retries. Never overwrite existing destination. Only same-volume moves, and only after complete filesystem safety traversal and fresh identity verification.
