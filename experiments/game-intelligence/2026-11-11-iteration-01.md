# Game Intelligence Lab — 2026-11-11, iteration 1

Scope: source inspection of main's app/smart_discovery.py, app/game_discovery.py, app/game_metadata.py, tests/test_smart_discovery.py. No production edits, releases, real downloads, or executable launches.

## Critical finding: structural evidence is not independent identity proof

Current score is `min(35 + 35*identity + 30*engine_structure + 20*store_manifest + 16*asset_signature,100)`, with auto-ready at >=96 if old enough. Thus a title-matching executable plus a `UnityPlayer.dll` file (or matching *_Data folder) reaches 100 even if the package is an unrelated utility. A title-matching executable plus Unreal-like structure similarly reaches 100. Engine evidence is a *category clue*, not an authenticated game identity.

Conversely, a legitimate game with an opaque executable name may remain in review. A false negative is acceptable for automation; a false positive is not.

## Reproducible surrogate scoring test

A standalone reproduction of the score formula (not a full integration test) yielded:
- Outer Wilds / OuterWilds.exe / Unity signal: score 100, auto-ready (positive)
- Music Player / MusicPlayer.exe / spoofed Unity signal: score 100, auto-ready (negative, **false positive**)
- Backup Manager / BackupManager.exe / Unreal signal plus assets: score 100, auto-ready (negative, **false positive**)
- Silent Hill 2 / SHProto.exe / Unity signal: score 72, review (game, expected auto-ready false)
- CCleaner / CCleaner.exe / no structural signal: score 56, review (negative)

Caveat: this surrogate does not execute the repository's entire pipeline. In particular, executable selection, filesystem stability, and blocking rules could affect end-to-end results. Need direct regression tests against repository code in next iteration. No statistically meaningful precision/recall claims yet.

## Further source-inspection risks

1. `_walk` deliberately skips ignored directories, but `candidates()` uses its own os.walk and a different ignore list. EXEs in `mods`, `tools`, `patch`, or `fix` may influence candidate ranking despite not being included in the structural inventory.
2. `_walk` returns `bool(queue)` as the truncated flag. If MAX_FILES is reached with queue empty, truncation can go unreported; if it is reached during iteration, inventory is incomplete. It should return an explicit `hit_limit` flag.
3. `_steam_manifest` treats a filename as manifest evidence; an arbitrary file called `steam_appid.txt` is not a verified product ID. `inspect_manifest_names` parses title claims but does not establish trusted provenance.
4. `move_verified` re-inspects but does not compare a durable tree fingerprint; a concurrent modification between inspection and rename remains possible. `os.rename` behavior and no-overwrite guarantee need Windows-specific verification, including case-insensitive destinations.
5. `scan_downloads` only inspects first 200 alphabetically sorted entries, which could starve later new downloads indefinitely.
6. Artwork title/edition correctness is not verified by this module; must be measured separately.

## Proposed architecture and experiment

Separate **classification** (game vs utility) from **identity** (canonical title/edition) and **movement authorization**. For auto-move require at least one strong product-identity anchor (validated known store ID with trusted install context, or independently verified executable signature/known game fingerprint), plus structural consistency and no conflicting evidence. For unknown preinstalled releases, prefer review until more independent evidence exists. Do not treat metadata self-claims as proof.

Next tests: import the actual repo and add regression fixtures for spoofed Unity/Unreal utility, misleading exe under tools, 1800+ files, 201+ downloads, mismatched manifest IDs, same-title editions, symlink/junction and concurrent mutation. Measure false auto-moves (target zero), precision/recall, title/edition accuracy and runtime. Add artwork-provider identity mapping test with deliberately ambiguous sequels/remasters.
