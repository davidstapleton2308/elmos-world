## Hypothesis and runnable prototype
Separate a trusted, independently established base-game identifier from untrusted folder/executable similarity, and explicitly abstain on edition identification unless edition-specific evidence exists. An ID written in an arbitrary manifest is not independent verification.

Executed a 10-row synthetic policy fixture in Python, comparing executable similarity >=0.85 as a **proxy baseline** (not the full app's auto-ready rule) against a trusted-ID-gated policy. Six rows carried fixture-supplied trusted base-game IDs, four did not; titles included Portal / Portal 2, Sims 3 / Sims 4, Control Ultimate Edition, Hogwarts Legacy Deluxe Edition, a utility, and a release-tagged folder. The fixture's trusted IDs are an oracle input for policy testing, not something the prototype discovered.

Observed: similarity proxy accepted 4/10 rows, including one Backup Manager utility with 0.963 similarity and one unverified Portal 2 row. Trusted-ID gate accepted 6/6 oracle-identified rows and 0/4 without an oracle ID; it abstained on **all ten edition claims**. Timing for this tiny run was 0.346 ms, not meaningful as a performance benchmark. No filesystem moves, artwork downloads, or emulator classification were exercised.

Crucial limitation: feeding fixture ground truth into the policy does **not** establish real-world precision or recall. It demonstrates abstention and the need for independent identity verification, not a working verifier. Do not report 100% production accuracy. Baseline threshold 0.85 is a deliberately simplified identity-only comparison.

## Architecture recommendation
Model `GameFamily -> BaseGame -> Edition -> Platform/StoreSKU -> Installation -> ArtworkAsset` with typed, namespaced identifiers and provenance. Do not equate executable names, arbitrary store-ID text files, or artwork filenames with canonical IDs. A verified base game may legitimately have `edition=unknown`; artwork should prefer edition-agnostic assets until verified, and never substitute sequel artwork.
