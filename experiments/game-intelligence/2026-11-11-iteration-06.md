## New hypothesis
A SQLite durable worklist with transactional batch completion and periodic reconciliation will survive a process restart and avoid permanent alphabetical starvation. It must not be confused with a fully safe Windows watcher or file-move authorization system.

## Actual disposable SQLite experiment
Ran Python's sqlite3 against a temporary on-disk database (deleted after test). Schema: identity PRIMARY KEY, path, status, first_seen, last_seen, attempts. Started with 10,000 alphabetical distractors plus `Z_NEW_GAME`; 200 jobs per cycle, 60 cycles. On each cycle after the first, removed one old entry, added two new entries, and reconciled. Explicitly closed/reopened the database at cycle 11 to simulate restart. Selection was oldest pending first; processed jobs updated inside a transaction. No real Downloads, game files, executables, or game folders were touched.

**Observed:** final extant rows 10,060; pending 0 after 60 cycles; `Z_NEW_GAME` discovered at cycle 51; 10,119 distinct processed identities (some were later removed). These numbers are for queue coverage only. They do not establish title precision/recall, emulator recognition, artwork accuracy, safe-move correctness, or real Windows throughput.

## Design issue uncovered
This prototype uses pathname as identity and marks a batch done in one transaction. Path-based identity cannot reliably follow renames; deleting absent jobs discards history; jobs should use a stable Windows volume/file identifier where available, plus a generation and path fallback. A crash *between* scanning a file and marking it done must be handled with leases/retries and idempotent results. Reconciliation must distinguish a disconnected volume from deletion and avoid deleting valid jobs during transient listing failures.

## Proposed next integration harness
- Implement durable `pending -> leased -> done/retry` state with lease expiry, attempt counters and backoff; inject crashes before and after classification commits.
- Windows-only fixture: NTFS file IDs, rename, symlink/junction, file-ID reuse, locked files, inaccessible subtrees, and directory watcher overflow.
- Reserve scan capacity for backlog even during a flood of new downloads, and measure 95th-percentile discovery latency.
- Add a separate full-tree safety traversal that fails closed on truncated, skipped or unreadable entries. Never move when only the recognition scan is complete.
- Run baseline and new code on the *same* fixture set and report actual game/emulator/artwork identity metrics independently.
