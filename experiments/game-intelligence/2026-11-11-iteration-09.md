# Game Intelligence Lab — iteration 9 (2026-11-11)

## Source verification
Read current main `app/smart_discovery.py` and the actual iteration-08 experimental note using GitHub connector. Main `move_verified` checks `target.exists()` then `os.rename(src,target)`; no operation-specific lock, no journal, no atomic no-replace guarantee.

## Hypothesis
A preliminary destination-exists check is insufficient against concurrent movers or destination creation. A mere directory reservation is not sufficient unless it is paired with a proper no-replace finalization and recovery protocol.

## Executed experiments
Ran real, disposable Python `tempfile` filesystem operations, using two threads synchronized with `threading.Barrier`:
1. Two workers simultaneously saw an absent destination and tried `os.rename`. One succeeded; the other failed with `FileNotFoundError`. The payload survived, but both workers entered the unsafe critical section.
2. Two workers used atomic `mkdir(destination)` reservation. One reserved, the other failed `FileExistsError`; the first then renamed the source into the empty destination. Payload survived. **Important**: on this POSIX test filesystem, `os.rename` replaced the empty reserved destination directory, so reservation did not itself guarantee a protected destination.
3. A deterministic adversarial interleaving: source exists, preflight observes absent target, competing actor creates an empty target, then `os.rename(source,target)`. Observed: rename **replaced the empty destination**, source disappeared, payload remained. This confirms the check-then-act race and invalidates any assumption that the existence check alone enforces no-replace.

## Observed metrics
- Naive two-worker trial: 1 success / 1 FileNotFoundError; 1 intact payload.
- Reserved two-worker trial: 1 success / 1 FileExistsError; 1 intact payload.
- Destination-injection trial: 1/1 empty target replaced despite preflight. This is a correctness violation even though this specific fixture lost no payload.
- All 3 trials ran on POSIX, not Windows NTFS; not statistical benchmarks, not a complete crash/concurrency proof. No real user files touched.
- Game classification precision/recall, title/edition, emulator and artwork identity: not tested in this iteration.

## New architecture recommendation
Use a per-source exclusive operation lock with generation fencing; durable SQLite move intent; pre-move full filesystem safety inventory; and a platform-specific **atomic no-replace** operation. For Windows, research and validate documented MoveFileEx/SetFileInformationByHandle semantics and same-volume restrictions on an NTFS CI runner, including races. Never treat a prior `exists()` check as a safety guarantee. For any reservation/staging approach, persist staging identities and use a finalization method that provably cannot overwrite. If no supported no-replace primitive can be established, keep unattended moves disabled. Reconcile crash recovery using persisted file identities and hashes; ambiguous states require review.
