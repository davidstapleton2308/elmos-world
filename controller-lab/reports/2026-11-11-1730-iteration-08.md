## Problem and design
The bridge's per-slot 3-second watchdog expires idle virtual devices even when the controller process is healthy but intentionally not emitting input. A heartbeat must refresh the lease **only when the selected slot already exists** and must never replay an input frame or resurrect an expired device.

New `heartbeat` JSON-lines operation takes a `slot`, validates it against the active controller dictionary, calls the existing monotonic `RenewLease(slot)`, and returns an acknowledged `{renewed:true,slot}` result. The Python `BridgeClient.heartbeat(slot, timeout=2)` sends the acknowledged request.

**Important safety rule:** Do not start a daemon that unconditionally renews leases independently of the physical input acquisition loop. A stalled reader could otherwise leave held inputs alive indefinitely. Future caller integration should emit heartbeats only on healthy, successfully polled idle frames and stop on source disconnect/error. Use a cadence comfortably below 3 seconds (for example 1 second), while treating delayed/failed responses as a fault. Input submissions already renew leases, so heartbeat is optional and should only be used for intentional idle periods.
