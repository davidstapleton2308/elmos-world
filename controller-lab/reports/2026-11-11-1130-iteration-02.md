## Root cause and fix
Repeated binary floating-point additions produce a value microscopically below an exact integer; `math.trunc` treats it as one less. The lost integer carries as residual, yielding net one-pixel drift after a full reversal. Snap values within an absolute 1e-12 of an integer before truncation, while preserving genuine fractional values (e.g. 0.999). No change to public method signatures.

- Fix commit: [c10f79f](https://github.com/davidstapleton2308/elmos-world/commit/c10f79fe996a3a53d4941ce7fed55eebaab6c256).

## Research and limitations
SDL3 represents relative mouse motion with float `xrel`/`yrel` and provides accumulated float relative deltas: https://wiki.libsdl.org/SDL3/SDL_MouseMotionEvent and https://wiki.libsdl.org/SDL3/SDL_GetRelativeMouseState. Elmo's integer-output boundary needs quantization that preserves total movement across reports. Floating-point snapping tolerance is intentionally tiny to avoid introducing meaningful extra movement. Alternative future design: compensated summation or fixed-point quantization for very long sessions.

A standalone Python numerical check reproduced the corrected 60/120/240 Hz totals, but the complete pytest suite and new GitHub CI results must be checked after commits. No physical controller validation was performed.
